# Предложение

## Зачем

Сейчас новых тренеров нельзя завести без ручной правки данных: в приложении нет раздела администрирования, хотя роль `platform_admin` уже есть у учётки, а вход уже отклоняет заблокированные учётки (**ADMIN-001**…**ADMIN-004**). Администратор платформы не может создать учётку со стартовым справочником упражнений, закрыть доступ уволенному тренеру или выдать новый пароль тому, кто его забыл. Остальной кабинет тренера уже готов, поэтому выдача доступа становится узким местом для подключения новых тренеров.

## Границы изменения

### Входит

- раздел администрирования в том же SPA и с той же сессией, доступный только учётке с ролью `platform_admin`;
- отдельный шелл раздела: заголовок «Администрирование», «Назад» возвращает в кабинет тренера, без полосы табов тренировок и контекста клиента;
- пункт «Администрирование» в Профиле, видимый только при `platform_admin`;
- без роли `platform_admin` прямой заход в раздел приводит к редиректу на список клиентов без каких-либо данных раздела, в том числе сразу после входа по ссылке в раздел;
- список других учёток тренеров: идентификатор (email) и статус «активен» или «заблокирован»; своя учётка не предлагается к блокировке и сбросу пароля;
- создание учётки тренера по email и первоначальному паролю: одной операцией появляется новая активная тренерская учётка со своим `trainerId` без роли `platform_admin` и со своей копией стартового справочника упражнений;
- блокировка и разблокировка учётки с подтверждением; заблокированная учётка не может войти, а её действующая сессия перестаёт приниматься;
- сброс пароля с подтверждением: администратор задаёт новый временный пароль, после успеха он показывается один раз;
- административный API с теми же правилами доступа: без сессии и без роли `platform_admin` запросы отклоняются;
- роль `platform_admin` через API и UI раздела не назначается и не снимается (**ADMIN-004**);
- раздел не показывает и не читает клиентов, планы и тренировки других тренеров (**TENANT-001**).

### Не входит

- смена своего пароля залогиненным пользователем (**AUTH-002**);
- одноразовые ссылки, письма и вариант «задать пароль при первом входе»;
- принудительная смена временного пароля при следующем входе;
- назначение и снятие роли `platform_admin`, удаление учёток, смена email;
- просмотр клиентов, планов и тренировок других тренеров;
- пустая сессия и экран активной тренировки из спецификации вкладки тренировки.

## Функциональности

### Новые функциональности

- `admin/trainer-account`: администрирование учёток тренеров платформенным администратором — доступ к разделу и его шелл, список учёток со статусом, создание учётки со стартовым справочником упражнений, блокировка и разблокировка, сброс пароля на временный.

## Внешнее влияние

- в HTTP API появляется административная группа операций над учётками тренеров; изменение аддитивное, существующие ответы не меняются;
- блокировка из раздела прекращает действие текущей сессии заблокированного тренера: его следующие запросы к тренерскому API отклоняются;
- в SPA появляются раздел `/admin` с отдельным шеллом и пункт «Администрирование» в Профиле для `platform_admin`.
