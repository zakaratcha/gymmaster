# Предложение

## Зачем

Сейчас тренер видит отдельную завершённую тренировку, её сравнение с планом и с прошлой похожей тренировкой. Но он не может посмотреть, как одно упражнение менялось у клиента от тренировки к тренировке (**HIST-001**, **UC-06**). Без этого прогресс по весам и подходам приходится собирать вручную, открывая каждую сессию. Особенно это мешает в зале: перед следующим подходом нужно быстро вспомнить, сколько клиент делал раньше. Карточка клиента, экран завершённой тренировки и вкладка текущей тренировки уже готовы, поэтому их можно сделать точками входа в историю.

## Границы изменения

### Входит

- история одного упражнения у одного клиента: хронология завершённых тренировок, в факте которых есть это упражнение, от новых дат к старым;
- в истории для каждой тренировки показаны дата и фактические подходы с весом в килограммах и повторами, в компактном формате как в макете (`4×8@82.5`);
- в историю попадают только завершённые тренировки текущего тренера и выбранного клиента; тренировки в процессе, тренировки других клиентов и других тренеров в историю не попадают;
- упражнение, которое позже убрали в архив, остаётся в истории, если оно есть в прошлых тренировках;
- экран истории с заголовком «История: <упражнение> · <клиент>» и таблицей «дата — подходы»;
- загрузка, пустая история и ошибка с повтором — по общим состояниям экранов;
- вход с карточки клиента: действие «История упражнения…» с выбором упражнения из справочника;
- вход со строки упражнения на экране завершённой тренировки;
- вход с вкладки текущей тренировки: иконочная кнопка в заголовке каждой карточки упражнения. История открывается поверх вкладки, а после закрытия пользователь возвращается на ту же вкладку, состояние тренировки при этом сохраняется;
- чтение истории через тренерский API с такой же изоляцией по тренеру, как у других тренерских данных: по чужому идентификатору нельзя понять, существует ли запись.

### Не входит

- блок «Текущее упражнение» на вкладке тренировки и само понятие текущего упражнения;
- график весов (переключатель «Таблица / График» из макета ждёт библиотеку графиков);
- столбец комментария из макета;
- запланированные подходы на те же даты рядом с фактом;
- список последних тренировок клиента с фильтром по тегу (**DASH-001**);
- действие «Вернуть в зал»;
- изменения сравнения с планом (**CMP-001**) и сравнения с прошлой тренировкой (**CMP-002**).

## Функциональности

### Новые функциональности

- `workout/exercise-history`: история одного упражнения у одного клиента по завершённым тренировкам. Включает экран истории и входы с карточки клиента, с экрана завершённой тренировки и с вкладки текущей тренировки.

## Внешнее влияние

- в тренерском HTTP API появляется чтение истории упражнения для клиента. Изменение аддитивное, существующие ответы не меняются;
- в SPA появляется экран истории упражнения, а на карточке клиента, на экране завершённой тренировки и на вкладке текущей тренировки — новые действия для перехода к нему.
