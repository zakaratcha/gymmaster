# auth/password Specification

## Purpose

Функциональность позволяет вошедшему тренеру сменить собственный пароль, подтвердив его текущим паролем. После смены прежние сессии учётки перестают действовать, а тренер остаётся в приложении с новой сессией.

## Requirements

### Requirement: Переход к смене пароля из Профиля

- **SHALL** в Профиле у любой вошедшей учётки, с ролью `platform_admin` или без неё, есть пункт «Сменить пароль».
- **SHALL** пункт «Сменить пароль» открывает экран «Смена пароля» по адресу `/account/password` внутри кабинета тренера.
- **SHALL** экран содержит поля «Текущий пароль», «Новый пароль», «Повтор нового» со скрытым вводом и действие «Сохранить».
- **SHALL** действие «←» на экране возвращает в Профиль `/account`.

#### Scenario: Открытие экрана из Профиля

- **GIVEN** тренер без роли `platform_admin` вошёл в приложение
- **AND** открыт Профиль
- **WHEN** он выбирает «Сменить пароль»
- **THEN** показывается экран «Смена пароля» с полями «Текущий пароль», «Новый пароль» и «Повтор нового»
- **AND** адрес страницы — `/account/password`

#### Scenario: Возврат в Профиль

- **GIVEN** тренер открыл экран «Смена пароля»
- **WHEN** он выбирает «←»
- **THEN** показывается Профиль
- **AND** адрес страницы — `/account`

### Requirement: Проверка повтора нового пароля

- **SHALL** при несовпадении «Нового пароля» и «Повтора нового» экран показывает ошибку «Пароли не совпадают».
- **MUST NOT** экран при несовпадении отправляет смену пароля, и пароль учётки не меняется.

#### Scenario: Повтор не совпадает

- **GIVEN** тренер вошёл с паролем `secret-123` и открыл экран «Смена пароля»
- **WHEN** он вводит текущий пароль `secret-123`, новый `new-secret-1`, повтор `new-secret-2` и выбирает «Сохранить»
- **THEN** экран показывает ошибку «Пароли не совпадают»

#### Scenario: Несовпадение повтора не меняет пароль

- **GIVEN** тренер вошёл с паролем `secret-123` и открыл экран «Смена пароля»
- **WHEN** он вводит текущий пароль `secret-123`, новый `new-secret-1`, повтор `new-secret-2` и выбирает «Сохранить»
- **AND** выходит из приложения
- **AND** входит с паролем `secret-123`
- **THEN** показывается Профиль с email тренера

### Requirement: Ошибка смены пароля на экране

- **SHALL** при отказе в смене пароля экран остаётся открытым и показывает текст ошибки, полученный от сервера.

#### Scenario: Неверный текущий пароль на экране

- **GIVEN** тренер вошёл с паролем `secret-123` и открыл экран «Смена пароля»
- **WHEN** он вводит текущий пароль `wrong-pass-1`, новый и повтор `new-secret-1` и выбирает «Сохранить»
- **THEN** экран показывает ошибку «Неверный текущий пароль»
- **AND** адрес страницы — `/account/password`

### Requirement: Успешная смена пароля на экране

- **SHALL** после успешной смены пароля показывается Профиль `/account`, и тренер остаётся в приложении без повторного входа.
- **SHALL** после выхода учётка входит с новым паролем, а вход с прежним отклоняется.

#### Scenario: Тренер остаётся в приложении

- **GIVEN** тренер вошёл с паролем `secret-123` и открыл экран «Смена пароля»
- **WHEN** он вводит текущий пароль `secret-123`, новый и повтор `new-secret-1` и выбирает «Сохранить»
- **THEN** показывается Профиль с email тренера
- **AND** адрес страницы — `/account`

#### Scenario: Вход с новым паролем

- **GIVEN** тренер сменил на экране пароль `secret-123` на `new-secret-1`
- **AND** вышел из приложения
- **WHEN** он входит с паролем `new-secret-1`
- **THEN** показывается Профиль с email тренера

#### Scenario: Вход с прежним паролем

- **GIVEN** тренер сменил на экране пароль `secret-123` на `new-secret-1`
- **AND** вышел из приложения
- **WHEN** он входит с паролем `secret-123`
- **THEN** форма входа показывает ошибку «Неверный логин или пароль»

### Requirement: Доступ к смене пароля без сессии

- **SHALL** смена пароля без сессии отклоняется ответом 403.
- **SHALL** без сессии на `/account/password` показывается форма входа.
- **SHALL** если сессия перестала действовать, пока экран «Смена пароля» открыт, после «Сохранить» показывается форма входа без перезагрузки страницы.

#### Scenario: Запрос без сессии

- **GIVEN** сессии нет
- **WHEN** выполняется запрос смены пароля
- **THEN** API возвращает ошибку 403

#### Scenario: Экран без сессии

- **GIVEN** сессии нет
- **WHEN** открывается адрес `/account/password`
- **THEN** показывается форма входа

#### Scenario: Сессия прекратилась на открытом экране

- **GIVEN** тренер вошёл с паролем `secret-123` и открыл экран «Смена пароля»
- **AND** та же учётка вошла с паролем `secret-123` на другом устройстве, и сессия на экране перестала действовать
- **WHEN** он вводит текущий пароль `secret-123`, новый и повтор `new-secret-1` и выбирает «Сохранить»
- **THEN** показывается форма входа

### Requirement: Смена пароля только своей учётки

- **SHALL** смена пароля принимает только текущий и новый пароль и меняет пароль учётки, которой принадлежит сессия запроса.
- **MUST NOT** запрос меняет пароль другой учётки, даже если содержит её идентификатор или email.

#### Scenario: Чужой идентификатор в запросе

- **GIVEN** тренеры A и B созданы с паролем `secret-123`
- **AND** тренер A авторизован в API
- **WHEN** тренер A меняет пароль с `secret-123` на `new-secret-1`, указав в запросе идентификатор и email тренера B
- **AND** тренер B входит с паролем `secret-123`
- **THEN** вход тренера B успешен

### Requirement: Проверка данных смены пароля

- **SHALL** смена отклоняется ответом 400 с ошибкой «Проверьте введённые данные», если текущий или новый пароль пуст или не является строкой.
- **SHALL** смена отклоняется ответом 400 с тем же текстом ошибки, что при создании учётки, если новый пароль короче 8 символов.
- **MUST NOT** отклонённая смена меняет пароль или сессию учётки.

#### Scenario: Короткий новый пароль

- **GIVEN** тренер с паролем `secret-123` авторизован в API
- **WHEN** он меняет пароль с `secret-123` на `short`
- **AND** входит с паролем `secret-123`
- **THEN** API возвращает ошибку 400 с текстом «Пароль должен быть не короче 8 символов»
- **AND** вход успешен

#### Scenario: Пустой пароль

- **GIVEN** тренер с паролем `secret-123` авторизован в API
- **WHEN** он отправляет смену пароля, где пуст один из паролей:
  - текущий пустой, новый `new-secret-1`;
  - текущий `secret-123`, новый пустой
- **AND** запрашивает текущего пользователя в той же сессии
- **THEN** API возвращает ошибку 400 с текстом «Проверьте введённые данные»
- **AND** запрос текущего пользователя успешен

#### Scenario: Поле отсутствует или не строка

- **GIVEN** тренер с паролем `secret-123` авторизован в API
- **WHEN** он отправляет смену пароля с телом:
  - `{ "newPassword": "new-secret-1" }`;
  - `{ "currentPassword": "secret-123" }`;
  - `{ "currentPassword": 123, "newPassword": "new-secret-1" }`;
  - `{ "currentPassword": "secret-123", "newPassword": 12345678 }`
- **AND** входит с паролем `secret-123`
- **THEN** API возвращает ошибку 400 с текстом «Проверьте введённые данные»
- **AND** вход успешен

### Requirement: Неверный текущий пароль

- **SHALL** смена отклоняется ответом 400 с ошибкой «Неверный текущий пароль», если текущий пароль не совпадает с паролем учётки.
- **MUST NOT** при неверном текущем пароле меняется пароль учётки или прекращается её сессия.

#### Scenario: Сессия остаётся действующей

- **GIVEN** тренер с паролем `secret-123` авторизован в API
- **WHEN** он меняет пароль с `wrong-pass-1` на `new-secret-1`
- **AND** запрашивает текущего пользователя в той же сессии
- **THEN** API возвращает ошибку 400 с текстом «Неверный текущий пароль»
- **AND** запрос текущего пользователя успешен

#### Scenario: Пароль не меняется

- **GIVEN** тренер с паролем `secret-123` авторизован в API
- **WHEN** он меняет пароль с `wrong-pass-1` на `new-secret-1`
- **AND** входит с паролем `secret-123`
- **THEN** вход успешен

### Requirement: Смена пароля с заменой сессии

- **SHALL** успешная смена одной операцией заменяет пароль учётки и выдаёт клиенту новую сессию, с которой тренер продолжает работу.
- **SHALL** после успешной смены все прежние сессии учётки перестают приниматься.
- **SHALL** если новая сессия не выдана, пароль учётки остаётся прежним.

#### Scenario: Работа продолжается в новой сессии

- **GIVEN** тренер с паролем `secret-123` авторизован в API
- **WHEN** он меняет пароль с `secret-123` на `new-secret-1`
- **AND** запрашивает текущего пользователя с сессией из ответа на смену
- **THEN** запрос текущего пользователя успешен

#### Scenario: Прежняя сессия перестаёт действовать

- **GIVEN** тренер с паролем `secret-123` авторизован в API
- **AND** запомнена сессия, выданная при входе
- **WHEN** он меняет пароль с `secret-123` на `new-secret-1`
- **AND** запрашивает текущего пользователя с запомненной сессией
- **THEN** API возвращает ошибку 403

### Requirement: Вход после смены пароля

- **SHALL** после смены учётка входит с новым паролем.
- **SHALL** вход с прежним паролем отклоняется ошибкой «Неверный логин или пароль».

#### Scenario: Новый пароль действует

- **GIVEN** тренер с паролем `secret-123` авторизован в API
- **WHEN** он меняет пароль с `secret-123` на `new-secret-1`
- **AND** входит с паролем `new-secret-1`
- **THEN** вход успешен

#### Scenario: Прежний пароль не действует

- **GIVEN** тренер с паролем `secret-123` авторизован в API
- **WHEN** он меняет пароль с `secret-123` на `new-secret-1`
- **AND** входит с паролем `secret-123`
- **THEN** вход отклоняется с ошибкой «Неверный логин или пароль»
