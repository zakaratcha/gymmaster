## Зафиксированные ответы

| Тема | Решение |
|------|---------|
| Ниша | Кабинет тренера: планирование тренировок клиентов |
| Модель оплаты | Нет; инструмент для себя |
| Платформа | Только веб |
| MVP-сценарии | См. список в разделе «MVP» ниже |
| Коммерция | Нет |
| ПДн / юр. требования | Не задаются (личный инструмент) |
| Команда | Один тренер + вайбкодер |
| **Сплит** | **Свободные теги** типа дня (например «ноги», «верх», «день А»); **без** обязательного цикла из N слотов. «Аналогичная» тренировка — та же строка-тег у того же клиента. |
| **Планирование вперёд** | У клиента можно создать **любое количество** будущих **планов** подряд («следующая», ещё одна за ней, …). Не ограничено «одной следующей» и не привязано к отдельному экрану «неделя в календаре» как единственному виду — но у каждого плана должна быть **плановая дата** (или явный порядок для сортировки «что дальше»). |
| **Авторизация** | **Публичной саморегистрации нет** (может появиться позже). **Все** учётки — **тренеры** (`trainer` + `trainerId`); у **части** дополнительно **`platform_admin`**. Роль **`platform_admin`** **нельзя** выдать или снять **из UI приложения** — только bootstrap/ops (см. **ADMIN-004**). **Администрирование** — **отдельный раздел** с **другим интерфейсом**, не второй вход. **Вход**, **выход**, **сессия**, **смена пароля**; **восстановление** пароля учётке — через пользователя с `platform_admin` и/или email (на выбор реализации). Изоляция по **`trainerId`**. **Клиенты** зала **без** личного кабинета. |
| **Единицы веса** | Только **кг** (в т.ч. в UI и в хранилище); переключателя lb/фунтов в MVP **нет**. |
| **Развёртывание** | **Один сервер** с backend и **SQLite** (файл на диске; не «только браузер + IndexedDB» как источник правды). Облако vs VPS — на усмотрение. См. `05-tech-and-data.md`. |
| **СУБД** | **SQLite** — однопользовательский/встраиваемый движок, данные в файле, без отдельного процесса СУБД. |
| **Справочник упражнений** | При **создании** **новой** учётки тренера из админ-раздела копируется **стартовый сид-лист**. Тренер **создаёт** и **редактирует** записи; **исключение из списка** — **архивация** (мягкое удаление): не показывается при выборе для новых планов/фактов, ссылки в уже сохранённой истории не ломаются (см. `EX-000`). |

### MVP (обязательные сценарии)

1. **Доступ:** пользователь с **`platform_admin`** создаёт и ведёт **другие** учётки тренеров; **каждая** учётка — тренер, работа только со **своим** `trainerId`; **`platform_admin`** из интерфейса **не** выдаётся.
2. Создать **индивидуальные планы** тренировок для клиента (в том числе **несколько** будущих подряд) с учётом **сплита** (теги).
3. Внести **фактически проведённую** тренировку: удобное добавление упражнений, изменение весов, числа подходов и т.п.
4. **Наглядно** видеть разницу: **план vs факт** по одной тренировке.
5. Видеть разницу / динамику относительно **прошлых аналогичных** тренировок (с учётом сплита).
6. **История** весов и подходов для **конкретного упражнения** у **этого** клиента.
7. **Удобное переключение** между клиентами при параллельном ведении нескольких человек.

## Исходный чеклист (архив формулировок)

Ниже — исходные формулировки вопросов; актуальные ответы — в таблице выше.

### 1. Ниша и аудитория

1. **Что главное:** личные тренировки посетителя, работа тренера с клиентами, администрирование фитнес-клуба, или комбинация?
2. **Кто платит:** конечный пользователь, клуб, корпоратив?
3. **Рынок и язык:** только RU, мультиязычность с первого дня?
4. **Конкуренты/референсы:** что нравится и что категорически не хочется повторять?

### 2. MVP и ценность

5. **Одна фраза:** какую боль закрывает первый релиз?
6. **Обязательные сценарии для MVP:** перечислите 3–5 «без этого не запускаем».
7. **Что откладываем** явно после MVP?

### 3. Платформы и устройства

8. **Где живёт продукт:** только web, только mobile (iOS/Android), PWA, десктоп?
9. Нужен ли **офлайн-режим** (зал без связи, запись подходов)?
10. **Доступность:** есть ли требования (WCAG, крупный шрифт, контраст)?

### 4. Учётные записи и роли

11. Регистрация: email, телефон, соцсети, приглашения от клуба?
12. **Роли:** гость, клиент, тренер, админ, суперадмин — что реально нужно в MVP?
13. Нужна ли **мультиорганизационность** (несколько клубов в одном аккаунте)?

### 5. Данные и контент

14. **Упражнения:** своя база, импорт, интеграция с каталогом (если есть)?
15. **Программы тренировок:** шаблоны, периодизация, автопрогрессия?
16. **Медиа:** видео техники, фото, только текст?
17. **История:** какие сущности храним обязательно (веса, повторы, RPE, заметки, фото прогресса)?

### 6. Коммерция и интеграции

18. **Оплата** в продукте в MVP или внешняя касса/CRM?
19. Интеграции: календарь, Apple Health / Google Fit, wearable, 1С, AmoCRM — что критично?
20. **Уведомления:** push, email, SMS, только in-app?

### 7. Комплаенс и риски

21. **ПДн:** РФ / ЕС / другое; нужен ли отдельный DPA, хранение в РФ?
22. Обработка **здоровья** как чувствительных данных — есть ли юр. ограничения?
23. **Модерация** пользовательского контента (фото, комментарии) нужна?

### 8. Команда и сроки

24. Состав команды (разработка, дизайн, продакт) и **желаемый дедлайн** MVP.
25. Предпочтения по стеку (если есть): язык бэкенда, БД, облако.
