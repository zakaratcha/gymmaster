# Видение и границы продукта

## Рабочее название

**GymMaster** — личный **веб**-кабинет тренера для планирования тренировок клиентов и учёта факта: упражнения, подходы, веса, наглядное сравнение плана с выполнением и с прошлыми однотипными тренировками (с учётом **сплита**).

## Контекст

- **Для кого сейчас:** все пользователи — **тренеры** (свой **`trainerId`**); у **части** из них дополнительно роль **администратора** для раздела выдачи учёток. **Новых** тренеров заводит пользователь с этой ролью. У каждого **`trainerId`** — **свои** клиенты и справочник.
- **Доступ:** **Публичной саморегистрации нет.** Роль **`platform_admin`** **нельзя** включить или выключить из UI приложения (только ops/bootstrap, см. **ADMIN-004**). **Администрирование** — отдельный интерфейс/раздел SPA, не второй вход. **Вход**, **выход**, **сессия**, **смена пароля** общие; сброс пароля другому пользователю — через пользователя с **`platform_admin`** (опционально позже — self-service по email). Конечные **клиенты** зала **не** входят в приложение; это карточки внутри кабинета тренера.
- **Монетизация:** нет; инструмент для собственного использования.
- **Комплаенс / ПДн:** отдельные требования не задаются; разумная осторожность при возможном выкладывании в сеть — на усмотрение автора.
- **Вес в интерфейсе и данных:** только **кг**; другие единицы не поддерживаются в MVP.
- **Интерфейс:** **телефон в зале** — основной сценарий для кабинета тренера; адаптив под узкий экран обязателен (подробнее — `04-non-functional-requirements.md`).

1. Быстро составлять **индивидуальные планы** тренировок под клиента — в том числе **цепочку** будущих планов («следующая», ещё одна и т.д., **без** искусственного лимита) — каждый с **тегом типа дня** из сплита.
2. Удобно вносить **факт** прошедшей тренировки: добавлять и переупорядочивать упражнения, менять число подходов, веса, повторы.
3. **Наглядно видеть:**
   - расхождение **план ↔ факт** по одной тренировке;
   - динамику относительно **прошлых аналогичных** тренировок (тот же **тег** типа дня у того же клиента);
   - **историю** по выбранному упражнению для этого клиента (веса и подходы во времени).
4. **Быстро переключаться между клиентами**, когда в зале ведёшь несколько человек подряд.

## Критерии успеха MVP

- Тренер может за сессию работы в зале: выбрать клиента → открыть/запланировать тренировку → зафиксировать факт → увидеть отличия от плана и от прошлой «такой же» тренировки.
- Переключение между двумя–тремя клиентами не превращается в «по пять кликов каждый раз».
- История по упражнению даёт ответ на вопрос «что мы делали и с каким весом последние разы».

## Глоссарий

| Термин | Значение |
|--------|----------|
| **Администратор платформы** | Дополнительная роль **`platform_admin`** на учётке **тренера**: управляет **созданием и сопровождением других** учёток тренеров (блокировка, сброс пароля). **Не** получает доступ к чужим клиентам, планам и фактам (кросс-тенантно). Интерфейс — **отдельный раздел** SPA. Назначение или снятие **`platform_admin`** **только вне** приложения (см. **ADMIN-004**). |
| **Тренер (учётка)** | **Каждая** учётка в системе — тренер: обязательны **`trainer`** и **`trainerId`**. Новые тренеры создаются пользователем с `platform_admin` (первая учётка(и) — bootstrap). Клиенты, планы, факты и справочник изолированы по `trainerId`. |
| **Клиент** | Сущность в системе (человек, которого ведёт тренер); без своего логина в MVP. |
| **Сплит** | У клиента — **набор свободных тегов** (меток типа тренировочного дня), без жёсткого цикла «день 1…N». Тег подбирается при плане/факте; можно добавлять новые по мере надобности. |
| **План** | Запланированная **на будущую дату** (или с явным порядком в очереди) структура тренировки: тег типа дня, упражнения, целевые подходы/вес/повторы. У клиента может быть **сколько угодно** таких записей вперёд. |
| **Факт** | **Завершённая** тренировочная сессия (`WorkoutSession` со статусом `completed`): что реально сделано, с временем окончания; может расходиться с планом. |
| **Аналогичная тренировка** | Прошлая тренировка с **тем же тегом** типа дня у того же клиента (для тренда и сравнения). |
