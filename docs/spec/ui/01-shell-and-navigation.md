# Оболочка и навигация

## Две «витрины» в одном SPA

| Режим | Кто видит | Назначение |
|-------|-----------|------------|
| **Кабинет тренера** | Все залогиненные | Клиенты, планы, факты, справочник упражнений |
| **Администрирование** | Только `platform_admin` | Учётки других тренеров, без доступа к их клиентам |

Переключение — из пункта **«Ещё» / «Профиль»** (не отдельный домен и не второй логин). **Выход** и **смена пароля** общие.

---

## Кабинет тренера: скелет экрана (мобильный приоритет)

Все экраны кабинета делятся на **слои сверху вниз**:

```
┌─────────────────────────────────────┐
│ Главная │ Анна ● │ Иван ○       ›   │  ← Самая верхняя строка: табы (если есть in_progress);
│ ◄──────────────────────── scroll ──► │    в подписи таба тренировки — имя + иконка статуса
├─────────────────────────────────────┤
│ [☰] Заголовок экрана     [···]        │  ← App bar под табами: меню, контекстные действия
├─────────────────────────────────────┤
│                                     │
│         основная область            │  ← ИЛИ полноэкранная вкладка «тренировка»
│                                     │
├─────────────────────────────────────┤
│  Клиенты  │  Упражнения  │  Ещё    │  ← Нижняя навигация (только в основном UI)
└─────────────────────────────────────┘
```

### App bar

- Располагается **сразу под полосой табов**, когда табы показаны; если активных тренировок нет и полоса табов **скрыта** — app bar **верхняя** строка экрана.
- Слева: **меню** (на узком экране) — дублирует/дополняет нижние вкладки при необходимости.
- По центру или слева после иконки: короткий **заголовок текущего экрана** (не дублировать в табе имя клиента для тренировки — оно только в табе).
- Справа: контекстные действия экрана (**Сохранить**, **Добавить**, **Готово**) или overflow **«···»**.

### Верхняя полоса табов: основной интерфейс и активные тренировки (**UX-002**)

- **Самый верх** кабинета тренера — **горизонтальная полоса табов** (при наличии хотя бы одной сессии `in_progress`). Если активных нет — полоса **скрыта**, первым идёт **app bar**, затем контент (и при необходимости блок «Клиент»).
- **Первый таб** — **основной интерфейс** (тот же стек, что описан в `02-trainer-screens.md`: клиенты, планы, история, нижние «Клиенты | Упражнения | Ещё»). Короткая подпись вроде **«Главная»** или **«Кабинет»**.
- **Каждый следующий таб** — **одна активная тренировка** (одна `in_progress`-сессия). В подписи **достаточно имени клиента** и **иконки статуса** (фаза: отдых / пора к подходу и т.п.). **Тег типа дня** в таб **не выносим** — он остаётся внутри экрана тренировки.
- Табов может быть несколько; **горизонтальная прокрутка** полосы, если не помещаются.
- **Иконка статуса** на табе (без уведомлений ОС): в соответствии с таймером отдыха на экране этой тренировки (`04-active-workout-tab.md`) — например **●** «идёт отдых», **○** «нет отдыха / пора к подходу»; конкретная графика — при визуальном дизайне.
- **Переключение табов** мгновенно меняет контент: либо основной интерфейс (нижняя навигация видна), либо **полноэкранный режим ведения тренировки** для выбранной сессии (нижнюю навигацию в этом режиме **скрываем**, чтобы не конкурировать с фокусом зала; вернуться в кабинет — первый таб или «Назад» на экране тренировки).
- Порядок табов тренировок: **по времени старта** сессии (раньше началась — левее среди табов тренировок; после **«Главной»**).

### Несколько клиентов: табы vs «Главная» (**UX-001**, **UX-002**)

- **Кто сейчас в зале** одновременно у нескольких людей — отражается **только верхними табами** тренировок: у каждого такого клиента свой таб (**имя + иконка статуса**). Отдельного «текущего клиента тренировки» в шапке **нет** и не нужен — он не конкурирует с табами и не дублирует их.
- **«Главная»** — про **кабинет без режима таба тренировки**: планы, карточка, история, список клиентов. Здесь **нет** одной глобальной сущности «текущий клиент приложения». Переключение «чью карточку / чьи планы смотрю» — через **список клиентов**, **недавние**, **поиск** (`02-trainer-screens.md`) и заголовки экранов внутри маршрута **клиента**; при необходимости **смена клиента** в том же потоке — в **app bar** или в теле экрана (не отдельная фиксированная полоса «Клиент: …» над всем кабинетом).

### Нижняя навигация (3 вкладки)

Видна **только в режиме основного интерфейса** (первый верхний таб).

| Вкладка | Корневой экран |
|---------|----------------|
| **Клиенты** | Список клиентов + поиск + недавние |
| **Упражнения** | Справочник упражнений тренера (рабочий список, не архивные при выборе в план/факт) |
| **Ещё** | Профиль: **смена пароля**, **выход**; если есть `platform_admin` — пункт **«Администрирование»** (переход в другой под-шелл) |

Вкладка **«Клиенты»** — основной **home** после входа.

## Экран без привязки к клиенте (основной интерфейс)

На **«Упражнения»** и других экранах **без** маршрута конкретного клиента полоски выбора клиента **нет**. Верхняя полоса табов **остаётся**, если есть сессии в зале.

---

## Шелл раздела «Администрирование»

Отдельное оформление (другой заголовок / цвет акцента по желанию), но тот же логин:

```
┌─────────────────────────────────────┐
│ ← Назад   Администрирование    [···]│
├─────────────────────────────────────┤
│                                     │
│         список учёток / формы       │
│                                     │
└─────────────────────────────────────┘
```

- **«Назад»** возвращает в кабинет тренера (например на **Ещё** или последний экран тренера).
- Полоса табов тренировок и контекст клиента в админ-разделе **не показываются** (админ не ведёт чужих клиентов из этого UI).

## Маршрутизация (ориентир для реализации)

**Вход — не отдельный URL.** **Форма входа** — это **состояние приложения** при отсутствии валидной сессии: на **любом** открытом маршруте показывается ввод **логина и пароля** (полноэкранно или оверлеем — по реализации). Адрес при этом **можно не менять** на выделенный «логин» или нормализовать позже — главное, что **нет** обязательного отдельного роута вида `/login` в смысле обязательной навигации «сначала только туда».

**Админка и роль:** если пользователь открыл **`/admin/...`** и после входа у учётки **нет** `platform_admin`, **админ-интерфейс не показывать**, выполнить **редирект на начальную страницу кабинета тренера** (тот же home, что после обычного входа — например список клиентов). То же при уже существующей сессии тренера без админ-роли при прямом заходе по ссылке в админку.

| Префикс / состояние | Содержимое |
|----------------------|------------|
| Нет сессии | На любом из префиксов ниже — **форма входа** (состояние), затем загрузка целевого экрана |
| `/` … `/clients` | Кабинет тренера |
| `/clients/:id/...` | Экраны в контексте клиента |
| `/exercises` | Справочник |
| `/account` или `/more` | Смена пароля, выход, ссылка в админку |
| `/admin/...` | Админ-контент **только** при `platform_admin`; иначе **редирект** в кабинет тренера |
| Состояние UI «открыт таб сессии S» | Тот же маршрут или query/hash для восстановления после перезагрузки — по решению |

Адрес влияет только на первую вкладку «Главная» — переход в другие табы не меняет адрес.

Точные пути — на усмотрение разработки; важно сохранить **разделение кабинет / админ** и **общую сессию**.
