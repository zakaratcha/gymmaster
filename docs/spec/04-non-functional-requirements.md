# Нефункциональные требования

Продукт — **веб**-кабинет: **все** учётки — **тренеры**; у **части** дополнительно **`platform_admin`** (выдаётся **не** из UI). Раздел администрирования — отдельный UI для управления **другими** тренерами. Мультитенантность по `trainerId`. Жёсткие облачные SLA не фиксируются.

## Производительность

- **NFR-PERF-001:** Экраны «активная тренировка», переключение между текущими сессиями и сравнения остаются отзывчивыми при десятках упражнений и сотнях сессий на клиента; целевой ориентир — **ввод подхода на телефоне** в зале без заметных лагов (не только десктоп).

## Надёжность и данные

- **NFR-REL-001:** Данные не должны теряться при обычном использовании: явное сохранение или автосохранение факта тренировки — по выбранной архитектуре.
- **NFR-REL-002:** Регулярный **бэкап** (ручной экспорт или автоматический дамп) рекомендуется как практика, не формальный SLA.

## Безопасность и изоляция

- **NFR-SEC-001:** В **публичном** деплое — **HTTPS** для всего трафика.
- **NFR-SEC-002:** Пароли — только в виде **стойкого хеша** (argon2/bcrypt и аналог); никогда в открытом виде в БД и логах.
- **NFR-SEC-003:** Сессии или JWT **с ограниченным временем жизни** и механизмом продления/ротации по практикам выбранного стека; защита от XSS/CSRF — по рекомендациям фреймворка.
- **NFR-SEC-004:** **Изоляция тенантов** на уровне приложения обязательна; **SQLite** (зафиксировано) — дисциплина фильтров в коде и индексы по `trainerId`; при возможной смене на **PostgreSQL** — дополнительно желательны **RLS**.
- **NFR-SEC-005:** **Rate limiting** на **вход** (тренер и админ) и на чувствительные админ-действия; при появлении **email-reset** — защита от спама.
- **NFR-SEC-006:** Формальные требования регуляторики **не** заданы; при хранении персональных данных клиентов тренеров — здравый смысл и минимизация излишних полей.

## Наблюдаемость

- **NFR-OBS-001:** Достаточно логов разработчика на этапе MVP; при публичном деплое — логирование неуспешных входов и подозрительных паттернов без записи паролей.

## UX

- **NFR-UX-001:** Интерфейс — **веб** с **обязательным** адаптивом под **узкий экран** (телефон в первую очередь; планшет). **Основной** сценарий — работа **тренера в зале** с мобильного устройства; ключевые потоки (текущие тренировки, ввод подходов, переключение клиентов и активных сессий) должны быть **полностью пригодны** на ширине типичного смартфона без горизонтального «ломления» макета. Десктоп для тренера — дополнительный, не единственный опорный формат; **админка** может быть ориентирована на широкий экран, но не должна ломаться на узком **без потери базовой функциональности**.
- **NFR-UX-002:** Доступность WCAG **не** обязательна для MVP.

## Совместимость

- **NFR-COMPAT-001:** Современные браузеры: **мобильные** Safari (iOS) и Chrome (Android) — **обязательный** минимум для кабинета тренера; десктопные Chrome / Firefox / Safari — для полноразмерной работы и админки.

## Масштабирование

- **NFR-SCALE-001:** Ориентир на **несколько** тренеров и **тысячи** записей на аккаунт; экстремальная нагрузка не проектируется.
